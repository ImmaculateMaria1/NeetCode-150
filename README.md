## Approach

For every problem, I work through three tiers of solutions before settling on the best one:

1. **Brute force** — the obvious solution, usually O(n²) or worse. Establishes correctness first.
2. **Better** — an intermediate improvement (often via sorting or a smarter loop structure).
3. **Optimal** — the best known time/space trade-off, typically using a hash map, hash set, two pointers, or a similar pattern.

## Why Java

Working through this in Java specifically to build fluency with:
- `HashMap` / `HashSet` for O(1) average lookups
- `ArrayList` for dynamic arrays
- Built-in utilities (`Arrays.sort()`, `Collections`, `Arrays.equals()`, etc.)
- Time/space complexity trade-offs that show up differently than in Python (e.g. boxing/unboxing overhead, fixed-size primitive arrays vs. wrapper-type collections)
